# 技能点定义唯一出处，金标起草与管线抽取共享定义、提示词各自成文

评测改造（JD F1 迭代）时的方法决定。

## 背景

金标由 LLM 起草（ADR-0011）经人工裁决冻结。管线抽取的技能召回远低于金标，需要改抽取提示词。两个陷阱：

1. 提示词与金标起草相同 → 同源污染，F1 度量提示词克隆度而非抽取质量（ADR-0004 同源防污染的同款问题）。
2. 两边"什么算技能点"的定义不一致 → 指标度量定义分歧而非抽取质量。

## 决定

1. **定义唯一出处**：`app/pipeline/constants.py` 的 `SKILL_DEFINITION`（工具、语言、框架、平台、方法、领域知识；只从原文、不推断、不泛化）。金标起草（`app/eval/draft.py`）与管线抽取（`app/pipeline/extract.py`）都引用它，措辞各自成文。
2. **提示词禁止引用金标统计**（如"每条约 25 个"）——对齐分布是调分，对齐定义是修系统。
3. **迭代只动抽取提示词的措辞与边界澄清，不动 SKILL_DEFINITION**：改定义 = 改规格 = 金标须按 ADR-0011 重新起草裁决。
4. 曾试验两段式抽取（第一段轻列表、第二段补结构化字段），实测召回反降（0.729 → 0.604，补全段丢弃名单项，并集保底也救不回），回退单段。列表行为已由金标起草侧验证，若将来重启两段式须重做该对照。

## 后果

- 草稿提示词语义不变（定义句原样外置），已裁决的金标不需要重裁。
- 评测对齐口径必须与生产一致（冻结阈值 + 余弦），评测索引必须带嵌入——缺失会把对齐退化成纯精确匹配，召回被结构性压低。
