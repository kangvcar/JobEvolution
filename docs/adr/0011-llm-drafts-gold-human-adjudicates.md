# 金标草稿由 LLM 起草，裁决权在人

词表扫描是标注员的替身（`scan.py` 自注），平均标 24 个/条，比抽取器设计范围（职责/要求段 8–10 个）宽，召回 0.37 的天花板由它钉死。改法：对每条 JD 把**原文**喂给 LLM，只许从原文抽技能点，产出当草稿进 `notes` 留痕（模型、日期、提示词版本）；再走 `verification.md` 两段修订——盲改对原文与词表，分歧回原文裁决，引不到原文的删。修订完冻结，重跑未 mock 三项。

LLM 只当标注员，不当答案。不许拿「互联网上该岗位通常要求什么」生成金标：不可溯（JD 里没写）、不可复现（活数据漂移）、与管线同源犯错互相污染——同一类问题 ADR-0004 已防过一遍。金标条目必须引得到 JD 原文或词表；F1 低于 0.90 报真数，不改金标迁就模型。简历金标走同一规矩。
