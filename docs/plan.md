# 成熟 MVP 分阶段实施路线

本文把智演从技术 Alpha 升级为公开可用的职业迁移决策 MVP。实现以根目录 [`CONTEXT.md`](../CONTEXT.md)、[`product.md`](product.md)、[`tech.md`](tech.md)、[`frontend.md`](frontend.md) 和 ADR 0040 至 0053 为准。

GitHub 路线总工单是 [#97](https://github.com/kangvcar/JobEvolution/issues/97)。19 个子工单已经建立原生父子关系和阻塞关系。旧版技术 MVP 总工单 #36 已在其子任务全部完成后关闭。工单正文是执行契约，本文说明阶段目标、交付顺序和整体验收。

## 实施原则

1. 数据可信先于报告文案。前端不能先接一套仍会变化的要求与诊断契约。
2. 确定性计算先于模型解释。岗位排序、要求性质、档位、换档条件和无法区分都由结构化规则决定。
3. 所有职业判断能回到证据。引用已有事实时带证据 ID，缺失时只写检查范围和“简历中未找到”。
4. 复用现有模块。技能对齐只有一个入口，匹配和换档模拟使用同一套服务端函数，公开与管理读取同一图谱版本。
5. 单岗失败只隔离单岗。它不能让其他岗位停止发布，也不能被拿来补足推荐数量。
6. 每个工单带一个能失败的检查。非平凡逻辑没有测试或最小可运行检查，不算完成。
7. 每个落地改动使用详细中文提交并立即推送。工单关闭前把验证命令和结果写入评论。

## 第一阶段：数据可信

这一阶段是整条路线的根。除首页公共壳 #108 外，不应在它完成前大规模开发新页面。

### #98 建立技能类型边界与三层归一

实现原子技能、品牌上下文、通用素质过滤、宽泛领域词约束、技能表面归一、技能合并提案和旧 ID 映射。

主要模块：

- `pipeline/extract.py`：输出原文、动作、职责上下文和候选类型。
- `pipeline/align.py`：成为唯一技能表面归一与规范对齐入口。
- `pipeline/gate.py`：把品牌裸提及送入观测中，把语义合并送入审核。
- `graph.py`：保存获批同义词和旧 ID 映射。

完成后，Prompt Engineering 与提示词工程能经批准映射到同一技能点，LangChain 与 LangGraph 等相关技术不会被误合并。本工单关闭后解锁 #99、#100、#103、#104。

### #99 用三态要求判定票替换默认必备

每份去重 JD 对同一技能点只投明确必备、明确加分或未标中的一票。未标票计覆盖率，不进入性质分母。明确性质达到 60% 且至少两个独立源支持才可写正式要求，否则只生成审核提案。

完成时必须能从管理接口读到三类票数、原文、来源、候选性质和理由。普通提及不能再自动变成必备。

### #100 实现要求组与要求等价数

同一 JD 的显式“或、任选、至少若干种”直接形成要求组。跨 JD 替代关系只生成要求组合并提案，人工批准前不得进入诊断。匹配、缺口、版本差分和数量上限全部按要求等价数工作。

必须覆盖 `min_required=1/2`、组内部分覆盖、独立职责重复技能和跨 JD 待审。C/C++/Go/Java 不因同属语言而自动成组。

### #101 增加诊断发布校验与岗位要求异常

建立一个共享校验入口，供岗位列表、推荐、岗位详情和诊断调用。它拦截空岗位定义、无有效必备要求、无证据、撤回证据、重复有效要求和未处理的岗位要求异常。

数量规则：

- 必备要求等价数默认上限 12。
- 全部正式要求等价数默认上限 24。
- 新增必备超过 `max(3, 上期必备 × 50%)` 时异常。
- 新增正式要求超过 `max(5, 上期正式要求 × 50%)` 时异常。

同时修复当前 Agent 工程师状态测试污染。修复必须从测试隔离和共享状态根因入手，不能改预期值。

### #102 提供岗位版本审核与一键全部批准 API

管理读取按岗位与待发布版本分组。批量批准跳过逐条人工阅读和独立审核模型，但仍执行证据存在、证据未撤回、摘录存在、无重复要求和岗位定义非空检查。

岗位要求异常可以通过非空放行理由越过。其他确定性校验失败时整批零写入。成功决定必须关联全部提案 ID 和同一个批量决定 ID，actor 只记录共享管理员会话。

### #103 重建可信岗位快照并审计可诊断岗位

用 #98 至 #102 的新规则重跑 `data/official-only/jd/`。任何技能点、要求边、岗位状态或岗位变化都不能手写。每个岗位输出定义、公司数、三类要求、要求组、要求等价数、变化和诊断发布校验结果。

专项检查大模型应用工程师、Agent 工程师、品牌裸提及、通用素质、CV/NLP 宽泛词和获批同义词。干净环境导入后的公开岗位、待审版本和失败岗位隔离必须与审计表一致。

阶段退出条件：

- 新审核快照通过 schema 与幂等导入。
- 所有公开要求有未撤回证据。
- 空岗位定义和异常要求岗位不会进入诊断。
- 大模型应用工程师不再以 25 项必备污染生成职业结论。

## 第二阶段：诊断内核

### #104 建立简历证据片段、证据级与校对契约

解析结果增加当前角色、工作年限、学历、经历、项目、技能、日期和最小原文摘录。证据级只分提及、使用、结果。用户补充但原文不存在的技能单列，不进入匹配分。

会话更新必须验证修正有原文支持。用户不能通过接口把“提及”直接升级为没有原文的“结果”。原始文件解析完成或失败后立即删除，会话仍为 Redis 一小时。

### #105 实现岗位推荐序、双岗方向结论与无法区分

推荐只读取可诊断岗位，按匹配档位、必备覆盖、有证据的岗位专属技能、可迁移工程能力排序，最后才用数据新鲜度和岗位证据量破同序。每个岗位返回前两条结构化理由。

用户选两个岗位后分别比较五个维度。匹配档位、必备覆盖、岗位专属证据数、可迁移工程能力数和最小换档要求等价数全部相同时，返回无法区分方向。新鲜度不能被写成用户更适合某岗。

### #106 生成有原文依据的 AI 简历分析与双轨行动

报告使用强 schema。确定性字段先完成，模型只根据可核对输入生成有限文案。必须返回方向结论、简历定位、优势风险、内容四态、关键词三组对照、全部改写候选、项目证据提示、最多三个能力任务和一份求职叙事稿。

模型返回未知证据 ID、编造数字、责任、规模或结果时，Pydantic 校验必须拒绝。

### #107 提供换档模拟与四个记忆点的数据契约

新增无状态模拟接口，复用服务端匹配与 `shift_set`。正式试算项只接受缺口、熟练级不足和要求组候选。观测中技能只回显到市场观察栏，不能改变假设档位。

诊断响应同时提供单岗简历证据关系、三个岗位的迁移数据，以及观测中技能的招聘样本出现比例、公司数、周期变化和证据摘要。

阶段退出条件：

- API 可以推荐三个岗位、选择两个岗位并生成双岗报告。
- 每条模型判断有证据 ID 或检查范围。
- 模拟请求前后会话数据完全一致。
- 观测项不能改变正式或假设档位。

## 第三阶段：公开体验

#108 与数据主线无依赖，可和 #98 同时开工。其余页面按 API 依赖逐步解锁。

### #108 重做公共壳、首页与用户界面用语

导航改为首页、岗位、市场变化。右侧保留开始诊断主按钮和管理文字入口。首页第一屏先讲职业迁移价值，展示脱敏方向结论；岗位图、故事和变化下移作依据。

公开页面统一使用去重招聘公司、截至某日的岗位要求、岗位要求、招聘样本出现比例、数据状态和岗位变化。内部术语只进入判断依据和管理页。

### #109 实现五步诊断

同一路由完成上传、校对、选择两个岗位、生成、报告。上传动作确认已展示的数据处理说明，不再放强制 checkbox。校对页确认个人与证据数据，选岗页在生成前显示图谱版本、岗位更新时间、数据状态和公司数量。

返回上一步保留当前会话。未通过诊断发布校验的岗位不可选择。减少动效设置下四拍取消位移，仍能说明正在处理什么。

### #110 构建结论、行动、依据三层报告与轻量导出

结论首屏只先放一句方向结论、当前档位、最大优势和最大阻碍。完整简历定位、分维度比较、行动与证据逐层展开。

报告支持复制有准确过期时间的对照链接、复制纯文本行动清单和浏览器打印。打印隐藏导航、按钮、抽屉、折叠内容和完整简历原文，服务器不生成 PDF。

### #111 实现换档模拟器与邻近岗位迁移地图

换档模拟器位于行动视图，每次选择调用服务端并处理过期响应。邻近岗位迁移地图只画三个岗位卡，移动端纵向排列，不做 14 岗蜘蛛网。

### #112 实现简历证据地图与市场信号雷达

证据地图一次只看一个岗位。桌面端两列连线，移动端改按岗位要求分组的证据列表。未连接简历经历使用中性文案。

市场信号雷达实现为可展开列表。每项显示比例、公司数、周期变化、未入要求原因和最短证据，不画多轴雷达图。

### #113 重做岗位页

岗位说明区先展示获批定义、三至五条典型职责、当前与上一周期、更新时间、数据状态和变化计数。桌面首次默认图谱，移动端默认要求清单，本次浏览选择写 `sessionStorage`。

要求清单按必备、加分、观测中分组。每条正式要求先显示确定性判定摘要，详细票数和证据按需展开。定义审核中的岗位禁用诊断。

### #114 将市场变化页改为问题式岗位卷宗

候选、萌芽、成型退为筛选与标签。卷宗直接回答形成原因、招聘公司、近期新增要求、与已有岗位的差异和是否值得关注。

无简历时只给市场关注建议，不输出个人转岗结论。有会话时才补个人档位和换档条件。候选仍只能看卷宗，别名不占候选结果。

阶段退出条件：

- 新用户不理解图谱术语也能完成五步诊断。
- 报告首屏能回答适配、阻碍与下一步。
- 四个记忆点使用同一份后端数据。
- 320px 宽无横向滚动，200% 缩放仍可完成诊断。

## 第四阶段：管理体验

### #115 重做岗位版本管理与批量审核界面

管理页按岗位与待发布版本分组，先显示定义、要求等价数、变化和异常，再列具体提案。岗位级预览使用求职者将看到的必备、加分和观测中清单。

一键全部批准显示岗位、版本和影响条数。普通版本确认一次即可，异常版本必须填写理由。确定性证据检查失败时显示具体错误并禁止提交。成功后显示批量决定 ID 和批准条数。

阶段退出条件：

- 管理员能逐条或批量处理岗位版本。
- 批量操作不调用独立审核模型，也不能发布无证据事实。
- Cookie、CSRF、登录限速、退出和自动审核开关没有回退。

## 工单执行规程

1. 从 [#97](https://github.com/kangvcar/JobEvolution/issues/97) 的原生子工单中选择没有开放阻塞、没有受让人的第一项。
2. 开工前领取工单并阅读它引用的 CONTEXT、产品、技术、前端和 ADR。
3. 先追踪现有调用链，复用已有图存储、会话、匹配和审核函数。
4. 每个工单只修改职责所需文件，不顺手重构相邻模块。
5. 接口变更先更新 Pydantic 模型和行为测试，再接前端。
6. 完成后在工单评论写行为变化、验证命令、结果、提交 SHA 和未做事项。
7. 使用详细中文 commit 并推送。确认远程同步后关闭工单。
8. 原生依赖自动解锁下一项。不要手工把仍受阻的工单标成完成。

## 全局验收矩阵

| 领域 | 必须证明 |
|---|---|
| 数据 | 技能类型、三态投票、要求组、要求等价数和异常拦截使用同一证据链 |
| 岗位 | 定义、职责、当前与上一周期、变化和判定摘要可核对 |
| 简历 | 每个匹配技能回到原文片段，用户补充不冒充命中 |
| 推荐 | 最多三个岗位、双岗比较、无法区分和换档条件由确定性字段产生 |
| AI 文案 | 不生成原文没有的数字、责任、规模或结果 |
| 模拟 | 假设技能不写会话，观测项不改变档位 |
| 管理 | 单条与批量审核可审计，无证据事实不能发布 |
| 隐私 | 上传前告知，原文件及时删除，匿名会话一小时，导出不延长保留 |
| 移动端 | 320px 无横向滚动，图形在移动端有列表替代 |
| 可访问性 | 键盘、焦点恢复、live region、减少动效、高对比度和打印可用 |
| 运行 | 干净导入、每日管线、数据陈旧、备份、告警和回滚仍可用 |
| 评测 | 真实数字公开，金标独立，测试与构建结果可重复 |

## 明确不做

- 账户体系、历史诊断、长期学习进度、提醒和打卡。
- 聊天机器人、AI 综合评分、ATS 分和简历完整度分。
- OCR、扫描件、旧版 `.doc`、LibreOffice 和版面重建模型。
- 自建课程库或图谱 `Resource` 节点。
- 14 岗全景迁移蜘蛛网、多轴雷达图、Timebar、暗色大屏和采集粒子。
- Postgres、Kafka、Graphiti/GraphRAG 整包、KuzuDB 或第二套图库。
- 为凑岗位数量手写技能、要求边、岗位状态、演化事件或发布结果。

这些范围只有新的产品决策和 ADR 才能重开，实现工单不得自行扩张。
