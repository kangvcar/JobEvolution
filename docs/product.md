# 智演

岗位能力图谱产品。从招聘数据流里发现新岗位、记下既有岗位的要求边怎么变。求职者对着一份简历做完一个决定：卡在哪、换邻近岗档位会不会更好、这个月补哪几样。

第一用户是已有 1–5 年后端或全栈经验、准备转向大模型应用或 Agent 岗位的人。学生、其他技术求职者和方向未定者仍走同一公开流程,系统根据简历经历调整解释,不建立用户类型模式；他们不主导首个公开 MVP 的默认故事、数据深度与验收。企业 HR 走管理后台,不跟求职者抢主路径。MVP 求职者免登录,简历停在会话里；后台一口令。

术语以仓库根目录 `CONTEXT.md` 为准。本文不另发明同义词。

视觉与页面以原型 [`docs/prototypes/signature-ui.html`](prototypes/signature-ui.html) 为准。IBM Plex、纸色、直角、accent hue 38。不做暗色大屏、采集流墙、演化时间轴回放。

## 定位

劳动力市场的岗位名在变，JD 里的技能点也在变。求职者拿到的往往是一份静态岗位描述，对不上「这个岗这周刚加上评测集构建」「Agent 工程师已经从大模型应用里拆出来了」。

智演把四领域（人工智能、大数据、智能系统、物联网）里的岗位做成可对账的图谱：每条要求边能点到证据，本周期变化画在切片差分上，对照简历只谈技能点档位，不把内部匹配分做成 0–100 海报。管线、待审、置信层留给发现页和管理页。

框架覆盖四领域，数据深度优先人工智能。下表 17 个规范岗位名是覆盖靶子，不是手录进图的种子。入谱岗、萌芽/成型、技能点由管线从 `data/` 里的本地 JD 长出（量级大约 17 岗、6 萌芽、约 60 技能点）。赛题那一对是 Agent 工程师（萌芽）与大模型应用工程师（成型）；诊断默认后者。候选不入谱；发现页三列能看见，不能对照简历、不能进工作台。

| 领域 | 成型 | 萌芽 |
|---|---|---|
| 人工智能 | 大模型应用工程师、机器学习工程师、算法工程师、多模态算法工程师 | Agent 工程师、模型评测工程师、提示词工程师 |
| 大数据 | 数据工程师、数据分析师、数据科学家 | 实时计算工程师 |
| 智能系统 | 嵌入式智能工程师、自动驾驶感知工程师 | 机器人软件工程师 |
| 物联网 | 物联网应用开发工程师、物联网平台工程师 | 边缘计算工程师 |

待审、不入谱：多模态标注质检员、知识库运维工程师、具身智能训练师。「大模型应用开发工程师」判为别名，并入大模型应用工程师。

## 用户与场景

**求职者。** 想转大模型应用、或已经在岗想看邻近岗。带一份含文本层的 PDF / docx 进来,先校对当前角色、工作年限、技能点、明确熟练级、简历证据片段对应关系与简历证据级；解析修正必须有原文支持,用户补充技能单列为「你补充的,简历尚未证明」。系统按岗位推荐序给出三个可诊断岗位和前两条理由,求职者可改选其中两个,再比较方向结论、缺口集、简历证据不足和换档条件。不注册。`.doc`、图片和扫描件不收。对照链接可带走,过期跟会话走；Redis 重启时允许提前失效。

**管理员。** 看待审队列：新岗位首次发布、核心必备技能新增、低置信抽取。批、改、驳。自动审核开关开启后,只有通过确定性校验和独立审核模型复核的高置信事实可自动入谱,流水仍留痕；中低置信继续人审,管理员仍可批准。待审是闸，不是第二套产品。

主路径两条：

1. 总览点故事 → 工作台看切片差分 → 对照这份岗。
2. 上传并校对简历 → 从三个推荐岗位中选两个 → 诊断给方向结论、简历修改与换档方案,仍停在 done 比较。

## 功能

赛题五块都落在产品里，求职者只看见其中面向人的那面。

### 多源采集

后台管线。冷启动吃仓库 `data/` 下所有本地 JD（不限一家招聘站、不限一份表）；ATS（Greenhouse / Lever / Ashby）、NCSS 高校就业、招聘站会话拦截作增量。独立源按去重后的公司计。求职者不操作采集。本周从哪来、拦下多少只在发现页；总览第一屏不展示管线。

### 新岗位发现

嵌入聚类 + LLM 簇判别（新词只辅助）。抽出的岗位名对齐上表 17 个靶子则并入该岗；对不上走发现簇。状态机：候选（未入谱，发现页可展示）→ 萌芽（≥3 独立源、90 天窗、判为新岗位而非别名）→ 成型（≥10 独立源，或持续 ≥6 个月，且岗位定义曾获批或自动通过）。发现页三列：候选 / 萌芽 / 成型（成型列切片 3 张，全名单在图谱左栏）。候选只开卷宗。别名并入已有岗，不占候选列，也不计入总览候选簇。批准仍在待审。岗位状态、要求边、技能点不手写。赛题那一对与「大模型应用开发工程师」的 ALIAS_OF 由管线从 JD 快照产出。

### 既有岗位能力更新

技能点入池要职责段 + 簇内覆盖率 ≥30%。覆盖率随周期变，不是搜索指数。本期覆盖率上升且刚过入池线 → 升值，先补；`valid_to` 或失效 → 可后补。中置信进待审；低置信不自动入谱。

要求边只使用原子技术技能或有职责上下文的领域知识。斜杠连接的框架、语言或平台必须拆开,原文表达任选时建立要求组；模型品牌默认保留在证据中,从同句动作抽取 API 集成、部署、微调或评测,没有动作只记观测中。沟通、团队协作、学习能力等通用素质不进入技能点、要求边和缺口集。

技能表述先做确定性表面归一:大小写、全半角、空格、明确标点差异和已获批旧名称直接对齐。Prompt Engineering 与提示词工程、CV 与计算机视觉等跨语言或缩写关系只能生成技能合并提案,人工核对定义与原文后写入共享同义词表；LangChain 与 LangGraph、GPT 与 Gemini、RAG 与向量数据库等相关技术禁止合并。批准合并不删除旧技能 ID,历史要求边与证据继续可追溯。

每份去重 JD 对入池技能点只投一张要求判定票。原文写明"必须"、"要求"、"熟练掌握"或列入明确任职要求时记明确必备,写明"优先"、"加分"时记明确加分,普通提及记未标。未标票能证明市场覆盖,不能把技能推成必备。明确必备票或明确加分票占已分类票至少 60%,且来自至少两个独立源,才可确定要求性质；其余情况只进待审。管理页同时展示三类票数和原文,人工决定也不抹掉原票,下个周期按新证据重新计算。

同一份 JD 明确写"任选"、"或"或"至少两种"时,按原文建立要求组并读取 `min_required`。多份 JD 分别要求 Python、Java、Go 或 C++ 时,只有这些技能支撑同一岗位职责、在单份 JD 中很少共同出现,且组合覆盖率达到 30%,系统才可生成要求组合并提案；人工批准前不能成组。技能类目相同不能证明可替代。组内技能按一个要求对账,不重复制造缺口；只有另一项独立职责明确单独要求某个组员时,该技能点才可另建要求边。

发布数量按要求等价数计算:独立要求边计 1,要求组按 `min_required` 计数。必备要求默认上限为 12,必备与加分合计默认上限为 24。相比上一发布版本,新增必备超过 `max(3,上期必备要求等价数 × 50%)`,或新增正式要求超过 `max(5,上期正式要求等价数 × 50%)`,均记为岗位要求异常；首个版本只检查数量上限。系统只暂停该岗位的推荐与诊断,其他岗位照常发布。管理员查看新增项、三类要求判定票和原文后,可以修正并重跑,也可以写明理由后放行。求职者只看到"该岗位数据正在校验,暂不可诊断",不能先看到污染后的职业结论。

### 岗位能力图谱

六类数据：领域、岗位、技能类目、技能点、证据、演化事件。画布只画领域（总览）或当前岗的类目和技能点。工作台画**当前所选岗位**的切片，并标切片差分（本周期新增 / 升值 / 已写 `valid_to`）。点技能点打开证据抽屉。演化事件列在发现页流水，不做时间轴回放。岗位不按初高级分裂，级别写在要求边上。

岗位页桌面端首次进入默认图谱视图,可切换到要求清单；移动端默认要求清单,仍可主动打开图谱。切换时保留当前岗位、筛选与周期,只在本次浏览会话记住选择。岗位说明区固定展示获批岗位定义、三到五条典型职责、当前切片日期、上一周期、岗位更新时间、数据状态,以及本周期新增、升值、失效数量。必备、加分和观测中分别成组,新增、升值与失效另有文字清单,不要求用户从画布猜变化。

每条正式要求先显示一句判定摘要,包含已分类票、明确性质票和独立源数量。"查看判断依据"再展开三类要求判定票、簇内覆盖率、证据摘要与最短原文。岗位定义未获批时显示"岗位定义审核中",允许查看市场卷宗,但不能进入简历诊断。

### 差距分析与学习路径

技能对齐：同义词优先，未命中再嵌入（阈值 0.85）。匹配分只在内部算：必备覆盖 + 0.3 加分，半档 0.5；经验、学历旁注不进档。求职者看到的是档位文案（高度匹配 / 基本匹配 / 有明显差距 / 不匹配），不是大数字。

简历中的技能点必须能回到简历证据片段。证据级分提及、使用、结果:只在技能栏或自我评价出现算提及；经历或项目写明任务中的使用算使用；写明本人责任以及数字、交付物或可核对结果算结果。最高只有提及时记简历证据不足。证据级不替代熟练级,不进入匹配分；方向结论可分别比较两个岗位的使用与结果证据数量,每条模型评价都能展开原文。

结论页先给简历定位判断:这份简历在当前可诊断岗位中最接近什么岗位,与两个对照岗位是否一致。随后最多列三项关键优势和三项主要风险。引用已有内容的判断都能打开简历证据片段；缺失项必须标明检查了哪个简历部分,且只能写"简历中未找到"。该判断不生成简历分数,也不把当前岗位集合内的结果说成用户的绝对职业身份。

教育、经历、项目、技能和成果证据分别标记为证据充分、已提及但证据较弱、简历中未找到或不适用,不合成完整度百分比。检查标准随经历调整:已有多年工作经历的人缺少校园项目不算风险,学生没有正式工作经历也不算错误。日期冲突先用确定性规则检查,其他风险必须引用原文。

岗位关键词对照只读取已发布要求边,并把获批同义词归到同一技能点。页面分为已有证据、只有提及和简历未找到证据三组,不显示 ATS 分数或关键词命中率,也不建议为命中率机械堆词。

简历改写建议逐条显示原文、当前问题、建议版本、使用的原文事实和仍需补充的事实。原文支持的事实可以重组与压缩；原文没有的数字、责任、技术规模和业务结果不得生成,只能用待补占位提示。每段项目根据内容只给一到两个项目证据提示:在线服务优先问吞吐、延迟或稳定性,RAG 项目优先问数据规模、召回质量或评测结果,模型调用优先问成本、准确率或业务效果。用户确认前不覆盖原文,建议版本和项目证据提示只有在用户补充真实内容、修改简历并重新上传后才能成为新的简历证据片段。

方向结论后给双轨行动清单。简历证明轨分析全部经历和项目,合并重复问题后按是否能补所选岗位的结果级证据、是否影响方向结论、简历证据不足和缺口解释排序；默认展示五条优先改写,其余按经历折叠在「其他可改」。能力提升轨按换档条件列最多三个任务,每项包含技能点、岗位职责证据、一条学习资源、一个可放进简历的交付物以及完成后会改变的判断。对照链接有效期内可勾选,不建立账户、长期进度、提醒或打卡。

行动页默认只为方向结论推荐的岗位生成一份 45 至 60 秒求职叙事稿,说明已有经验如何迁移、为什么转岗和最可信的岗位证据。用户切换目标岗位时重新生成,不同时堆两份。叙事稿只能使用简历原文与用户确认的事实,缺失内容保留待补提示。

学习路径按换档条件排序，不是按缺口出现顺序取前 5。每步四样：技能点、职责段摘录、一条能打开的链接、为何先补它。不自建课程库。赛题那一对可预置几门课的 URL，不进谱。路径覆盖抽检换档条件上的技能点，不定准确率。

同一简历在当前发布版本的全部可诊断岗位中逐层比较匹配档位、必备技能覆盖、有简历证据的岗位专属技能数和可迁移工程能力数,最后以数据新鲜度与证据充分度破同序,最多给三个岗位推荐；用户看到每岗前两条理由并可改选两个。某个岗位未通过诊断发布校验时只排除该岗位,不足三个就展示实际数量,不拿失败岗位补位。方向结论由模型解释必备技能覆盖、简历证据级、可迁移工程能力、岗位专属经历和经验学历风险,不生成新的综合分；默认故事是大模型应用工程师 ↔ Agent 工程师。换岗停在 done,不重传简历。

报告首屏固定为一句方向结论,下方只放当前适配档位、最大优势和最大阻碍。结论使用"已有基础、当前更接近的岗位、主要阻碍"结构,每项都能打开简历证据和岗位依据。两个岗位处于同一档位,岗位专属证据和换档条件也没有决定性差异时,系统写"当前简历证据不足以明确区分",不强选胜者；两个岗位仍分别给最小换档方案。

诊断报告保留四个产品记忆点：

- 换档模拟器的正式试算项只接受缺口、熟练级不足和要求组候选技能,用现有匹配规则即时重算两个对照岗位与邻近岗位。结果固定标为"假设结果,尚未被简历证明",不修改简历技能、证据级或正式方向结论；默认选中最小换档组合,用户可继续试其他组合。观测中技能单列为市场观察项,不进入试算输入。
- 简历证据地图一次只打开一个岗位。左侧按经历与项目列简历证据片段,右侧列正式要求,连线标明提及、使用或结果。未连接的要求写"简历未找到证据"；未连接的经历只写"与当前岗位要求未建立联系",不能判为无价值或表达缺口。
- 邻近岗位迁移地图只展示两个对照岗位和岗位推荐序中的一个邻近岗位,逐岗显示当前档位、最小换档技能数、共享能力和独有要求。点击邻近岗位可替换当前对照对象；岗位不足三个时展示实际数量。
- 市场信号雷达不用多轴雷达图,按技能点列簇内覆盖率、独立源数量、周期变化、代表性证据摘要和未进入正式要求的原因。固定说明"市场开始提,但还没进要求,不算你的缺口"。观测项可以加入换档模拟器的市场观察栏,但不进入假设计算或改变正式档位。

### 审核与直通

待审是幻觉防控的最后一闸。新岗位首次发布和既有岗能力更新共用。直通默认关。关着时中高也进待审；开了只跳过中高的人批，演化事件记自动通过。低层证据底线不跳过。

### 市场变化卷宗

候选、萌芽和成型保留为筛选与状态标签,卷宗主体改用求职者的问题组织:为什么系统认为岗位正在形成、哪些公司开始招聘、本周期新增什么要求、与最接近的已有岗位有什么区别、现在是否值得关注。公司按规范名称去重,默认显示五家和总数,渠道另列；证据仍只公开最短摘录。

没有简历会话时,"是否值得关注"只根据岗位状态、证据充分度、数据新鲜度和近期变化给市场关注建议,不替用户判断是否转岗。完成诊断后才补充个人档位与换档条件。

### 分析前告知

上传区在用户选择文件或拖放前写明支持格式、必要简历文本会发送给当前模型服务商、产品数据库不保存简历,以及匿名会话最长保留一小时。隐私详情放在同区折叠展开；上传动作即表示确认本次处理范围,不增加强制 checkbox,也不能在没有合同与配置依据时承诺服务商绝不留存。

校对页要求用户确认当前角色、工作年限、学历、技能、明确熟练级和简历证据级。选岗页在"生成对照"前展示图谱发布版本、两个岗位更新时间、数据状态、独立源数量,并说明报告只依据校对后的简历内容与当前图谱版本。未通过诊断发布校验的岗位不可选择,这些信息不单独增加第六步。

报告可以复制一小时对照链接并显示准确失效时间,也可以把双轨行动清单复制为纯文本。"打印 / 保存为 PDF"只调用浏览器打印能力,输出结论、行动和必要依据,不打印交互控件、折叠内容或完整简历原文。服务器不生成文件,匿名会话仍按原时间过期。

求职者界面使用人话:独立源显示为"去重招聘公司",切片显示为"截至某日的岗位要求",要求边显示为"岗位要求",簇内覆盖率显示为"招聘样本出现比例",置信层显示为"数据状态",演化事件显示为"岗位变化"。内部术语只在判断依据和管理页出现,页面标题与按钮不使用数据库结构命名。

## 信息架构

主导航三项「首页 · 岗位 · 市场变化」,顶栏右侧固定「开始诊断」主按钮与「管理」入口。管理仍可见,但视觉上不与求职者主操作同权。

| 路由 | 页面 | 谁用 | 职责 |
|---|---|---|---|
| `/` | 首页 | 求职者 | 第一屏说明职业迁移价值,主按钮上传简历比较岗位,次按钮打开大模型应用与 Agent 示例,并展示一份脱敏方向结论；岗位图、发现故事与能力变化下移作数据依据 |
| `/graph` | 岗位 | 求职者 | 岗位说明区；领域 / 技能类目 / 级别筛选；图谱 / 要求清单切换；切片差分、判定摘要与证据 |
| `/diagnose` | 开始诊断 | 求职者 | 同一路由内依次上传简历、校对解析、选择两个岗位、生成对照、查看报告。支持对照链接 |
| `/discover` | 市场变化 | 求职者 | 按用户问题组织岗位卷宗,候选 / 萌芽 / 成型作为筛选；展示公司、变化、相近岗位与市场关注建议 |
| `/admin` | 管理 | 管理员 | 口令门。待审默认页；直通开关；确认 / 驳回 / 证据。低置信可批，不记自动通过 |

诊断 done 顶部固定两个比较岗位、方向结论和切换操作,正文分三个主视图：

1. **结论**：方向结论、简历定位判断、邻近岗位迁移地图、两个岗位的分维度比较、最多三项关键优势与三项主要风险、简历内容状态、推荐理由、档位与换档条件；缺口集只写「简历未找到证据」,不推断真实能力
2. **行动**：换档模拟器、双轨行动清单与当前推荐岗位的一份求职叙事稿。简历证明轨默认展示五条优先改写并可展开全部；能力提升轨按换档条件列最多三个任务
3. **依据**：简历证据地图、岗位要求边、岗位关键词对照、市场信号雷达、最小岗位证据摘要、缺口集、熟练级差异、对账表、计分公式和岗位切片；另列对齐痕迹、简历多出来的技能点和已覆盖。半档 0.5、加分 0.3 只写在这里

简历原文不常驻占据半屏。点方向结论、改写建议或对账项时从抽屉打开对应简历证据片段,关闭后焦点回到触发项。移动端依据视图用技能分组列表代替需要横向滚动的岗位切片。

空态与失败：解析失败写原因 + 可重传，不道歉。换简历或离开诊断页则中止本次分析。邻近岗换岗不停分析。

岗位名录不进主导航。从总览图或工作台进某一岗即可。

## 给实现的约束

- 求职者第一。管理口令入口可以看见，不做成第二套产品。
- 画面跟原型走。新视觉决策先改原型再改本文。
- 求职者文案用人话；对账表、证据抽屉、术语表用 `CONTEXT.md` 的词。技能类目不对账。观测中不是缺口。
- 17 个规范岗位名是对齐靶子。技能点、要求边、岗位状态从 `data/` 本地 JD 管线长出，不要手录进 `bootstrap.py`。
- 赛题那一对由管线从 JD 快照产出，不要手写状态或演化事件。
- 学习路径按换档条件排序。
- 三项准确率按 `CONTEXT.md`：技能点 set-based F1 ≥0.90。匹配评测喂金标缺口集，不喂解析输出。
