# 智演

岗位能力图谱产品。从招聘数据流里发现新岗位、记下既有岗位的要求边怎么变，求职者对着一份简历看自己卡在哪、下一步补什么。

第一用户是新一代信息技术领域的求职者、学生、转行者。企业 HR 走管理后台，不跟求职者抢主路径。MVP 求职者免登录，简历停在会话里；后台一口令。

术语以仓库根目录 `CONTEXT.md` 为准。本文不另发明同义词。

视觉与页面以原型 [`docs/prototypes/signature-ui.html`](prototypes/signature-ui.html) 为准（[原型工单](https://github.com/kangvcar/JobEvolution/issues/11)）。IBM Plex、纸色、直角、accent hue 38。不做暗色大屏、采集流墙、演化时间轴回放。

## 定位

劳动力市场的岗位名在变，JD 里的技能点也在变。求职者拿到的往往是一份静态岗位描述，对不上「这个岗这周刚加上评测集构建」「Agent 工程师已经从大模型应用里拆出来了」。

智演把四领域（人工智能、大数据、智能系统、物联网）里的岗位做成可对账的图谱：每条要求边能点到证据，岗位状态能看见独立源，对照简历只谈技能点档位，不把内部匹配分做成 0–100 海报。

框架覆盖四领域，数据深度优先人工智能。演示集：17 岗、6 萌芽、约 60 技能点。赛题那一对是 Agent 工程师（萌芽）与大模型应用工程师（成型）；诊断默认后者。完整名单见 [决策:首批岗位覆盖清单](https://github.com/kangvcar/JobEvolution/issues/18)。

## 用户与场景

**求职者。** 想转大模型应用、或已经在岗想看邻近岗。带一份 PDF/Word 进来，选目标岗位，看缺口、半档、换档条件、学习路径。不注册。

**管理员。** 看待审队列：新岗位首次发布、核心必备技能新增、低置信抽取。批、改、驳。直通开关开着时中高置信自动入谱，流水仍留在队列里。低置信没有自动审核结论，不可直通。

主路径两条：

1. 总览点萌芽岗 → 图谱工作台看切片 → 对照简历。
2. 诊断直接选领域和岗位、放简历、出报告；报告里点技能点进工作台。

## 功能

赛题五块都落在产品里，求职者只看见其中面向人的那面。

### 多源采集

后台管线。ATS（Greenhouse / Lever / Ashby）、NCSS 高校就业、招聘站会话拦截、冷启动公开集。独立源按去重后的公司计。求职者不操作采集；总览和发现用同一口径展示本周 JD 从哪来、拦下多少。

### 新岗位发现

嵌入聚类 + LLM 簇判别（新词只辅助）。状态机：候选（只在待审可见）→ 萌芽（≥3 独立源、90 天窗、判为新岗位而非别名）→ 成型（≥10 独立源，或持续 ≥6 个月，且岗位定义曾获批或自动通过）。发现页看板按这三列排。别名并入已有岗，不单列。

### 既有岗位能力更新

技能点入池要职责段 + 簇内覆盖率 ≥30%。覆盖率随周期变，不是搜索指数。新增且热 → 升值，先补；`valid_to` 或失效 → 可后补。中置信进待审；低置信不入谱。

### 岗位能力图谱

六类节点：领域、岗位、技能类目、技能点、证据、演化事件。岗位不按初高级分裂，级别写在要求边上。工作台只画**当前所选岗位**的类目和技能点，深色必备、浅色加分。点技能点打开证据抽屉。

### 差距分析与学习路径

技能对齐：同义词优先，未命中再嵌入（阈值 0.85）。匹配分只在内部算：必备覆盖 + 0.3 加分，半档 0.5；经验、学历旁注不进档。求职者看到的是档位文案（高度匹配 / 基本匹配 / 有明显差距 / 不匹配），不是大数字。

学习路径取缺口与半档前几项，每步挂一条能溯源的资源（职责段摘录或证据）。不自建课程库。路径覆盖抽检，不定准确率。

### 审核与直通

待审是幻觉防控的最后一闸。新岗位首次发布和既有岗能力更新共用。直通默认关，开了只跳过中高置信的人批，演化事件记自动通过。低层证据底线不跳过。

## 信息架构

主导航四项 + 顶栏右「管理」。

| 路由 | 页面 | 谁用 | 职责 |
|---|---|---|---|
| `/` | 总览 | 求职者 | 四领域岗位图；萌芽/谱内/待审计数；新岗位发现与既有岗更新各一条故事；发现管线、技能热度、演化流水 |
| `/graph` | 图谱 | 求职者 | 领域 / 技能类目 / 级别筛选；左岗位列表；中当前岗切片；右定义、独立源、技能点表、证据 |
| `/diagnose` | 诊断 | 求职者 | 一页三态。idle：领域、目标岗位、简历。run：四拍对齐过程。done：左简历预览，右对照报告 |
| `/discover` | 发现 | 求职者 | 候选 / 萌芽 / 成型看板与卷宗；与总览同一套管线、热度、流水 |
| `/admin` | 管理 | 管理员 | 口令门。待审默认页；直通开关；确认 / 驳回 / 证据 |

诊断 done 报告四组，避免一长串同款列表：

1. **判断**：AI 总结、档位与四格（必备覆盖、半档、经验、学历）、目标岗状态、换档条件
2. **定位**：对照小图谱、类目覆盖（类目只导航、不对账）、邻近岗（同一简历换岗仍停在 done）
3. **行动**：学习路径（每步一条资源）、对账表（技能点 / 对照 / 简历 / 岗位 / 边 / 证据）
4. **解释**：对齐痕迹、观测中（写明不是缺口）、简历多出来的技能点、已覆盖

空态与失败：解析失败写原因 + 可重传，不道歉。换岗、换简历、离开诊断页则中止本次分析。

岗位名录不进主导航。从总览图或工作台进某一岗即可。

## 非目标与后续

本期不做：账户体系、历史诊断存档、订阅推送、自建学习内容库、评委 PPT / 演示视频。

Roadmap 只列条目：登录后保存对照、追踪某一萌芽岗、把学习路径接到真实课表。细节不在本文展开。

## 给实现的约束

- 求职者第一。管理口令入口可以看见，不做成第二套产品。
- 画面跟原型走。新视觉决策先改原型再改本文。
- 文案用术语表。技能类目不对账。观测中不是缺口。
- 三项准确率按 `CONTEXT.md`：技能点 set-based F1 ≥0.90。匹配评测喂金标缺口集，不喂解析输出。
