# 智演

岗位能力图谱产品。从招聘数据流里发现新岗位、记下既有岗位的要求边怎么变。求职者对着一份简历做完一个决定：卡在哪、换邻近岗档位会不会更好、这个月补哪几样。

第一用户是已有 1–5 年后端或全栈经验、准备转向大模型应用或 Agent 岗位的人。学生、其他技术求职者和方向未定者仍走同一公开流程,系统根据简历经历调整解释,不建立用户类型模式；他们不主导首个公开 MVP 的默认故事、数据深度与验收。企业 HR 走管理后台,不跟求职者抢主路径。MVP 求职者免登录,简历停在会话里；后台一口令。

术语以仓库根目录 `CONTEXT.md` 为准。本文不另发明同义词。

视觉与页面以原型 [`docs/prototypes/signature-ui.html`](prototypes/signature-ui.html) 为准。IBM Plex、纸色、直角、accent hue 38。不做暗色大屏、采集流墙、演化时间轴回放。

## 定位

劳动力市场的岗位名在变，JD 里的技能点也在变。求职者拿到的往往是一份静态岗位描述，对不上「这个岗这周刚加上评测集构建」「Agent 工程师已经从大模型应用里拆出来了」。

智演把四领域（人工智能、大数据、智能系统、物联网）里的岗位做成可对账的图谱：每条要求边能点到证据，本周期变化画在切片差分上，对照简历只谈技能点档位，不把内部匹配分做成 0–100 海报。管线、待审、置信层留给发现页和管理页。

框架覆盖四领域，数据深度优先人工智能。下表 17 个规范岗位名是覆盖靶子，不是手录进图的种子。入谱岗、萌芽/成型、技能点由管线从 `data/` 里的本地 JD 长出（量级大约 17 岗、6 萌芽、约 60 技能点）。赛题那一对是 Agent 工程师（萌芽）与大模型应用工程师（成型）；诊断默认后者。候选不入谱；发现页三列能看见，不能对照简历、不能进工作台。

| 领域 | 成型 | 萌芽 |
|---|---|---|
| 人工智能 | 大模型应用工程师、机器学习工程师、算法工程师、多模态算法工程师 | Agent 工程师、模型评测工程师、提示词工程师 |
| 大数据 | 数据工程师、数据分析师、数据科学家 | 实时计算工程师 |
| 智能系统 | 嵌入式智能工程师、自动驾驶感知工程师 | 机器人软件工程师 |
| 物联网 | 物联网应用开发工程师、物联网平台工程师 | 边缘计算工程师 |

待审、不入谱：多模态标注质检员、知识库运维工程师、具身智能训练师。「大模型应用开发工程师」判为别名，并入大模型应用工程师。

## 用户与场景

**求职者。** 想转大模型应用、或已经在岗想看邻近岗。带一份含文本层的 PDF / docx 进来,先校对当前角色、工作年限、技能点与明确熟练级；系统按岗位推荐序给出三个可诊断岗位和前两条理由,求职者可改选其中两个,再比较方向结论、缺口集、简历证据不足和换档条件。不注册。`.doc`、图片和扫描件不收。对照链接可带走,过期跟会话走；Redis 重启时允许提前失效。

**管理员。** 看待审队列：新岗位首次发布、核心必备技能新增、低置信抽取。批、改、驳。自动审核开关开启后,只有通过确定性校验和独立审核模型复核的高置信事实可自动入谱,流水仍留痕；中低置信继续人审,管理员仍可批准。待审是闸，不是第二套产品。

主路径两条：

1. 总览点故事 → 工作台看切片差分 → 对照这份岗。
2. 上传并校对简历 → 从三个推荐岗位中选两个 → 诊断给方向结论、简历修改与换档方案,仍停在 done 比较。

## 功能

赛题五块都落在产品里，求职者只看见其中面向人的那面。

### 多源采集

后台管线。冷启动吃仓库 `data/` 下所有本地 JD（不限一家招聘站、不限一份表）；ATS（Greenhouse / Lever / Ashby）、NCSS 高校就业、招聘站会话拦截作增量。独立源按去重后的公司计。求职者不操作采集。本周从哪来、拦下多少只在发现页；总览第一屏不展示管线。

### 新岗位发现

嵌入聚类 + LLM 簇判别（新词只辅助）。抽出的岗位名对齐上表 17 个靶子则并入该岗；对不上走发现簇。状态机：候选（未入谱，发现页可展示）→ 萌芽（≥3 独立源、90 天窗、判为新岗位而非别名）→ 成型（≥10 独立源，或持续 ≥6 个月，且岗位定义曾获批或自动通过）。发现页三列：候选 / 萌芽 / 成型（成型列切片 3 张，全名单在图谱左栏）。候选只开卷宗。别名并入已有岗，不占候选列，也不计入总览候选簇。批准仍在待审。岗位状态、要求边、技能点不手写。赛题那一对与「大模型应用开发工程师」的 ALIAS_OF 由管线从 JD 快照产出。

### 既有岗位能力更新

技能点入池要职责段 + 簇内覆盖率 ≥30%。覆盖率随周期变，不是搜索指数。本期覆盖率上升且刚过入池线 → 升值，先补；`valid_to` 或失效 → 可后补。中置信进待审；低置信不自动入谱。

### 岗位能力图谱

六类数据：领域、岗位、技能类目、技能点、证据、演化事件。画布只画领域（总览）或当前岗的类目和技能点。工作台画**当前所选岗位**的切片，并标切片差分（本周期新增 / 升值 / 已写 `valid_to`）。点技能点打开证据抽屉。演化事件列在发现页流水，不做时间轴回放。岗位不按初高级分裂，级别写在要求边上。

### 差距分析与学习路径

技能对齐：同义词优先，未命中再嵌入（阈值 0.85）。匹配分只在内部算：必备覆盖 + 0.3 加分，半档 0.5；经验、学历旁注不进档。求职者看到的是档位文案（高度匹配 / 基本匹配 / 有明显差距 / 不匹配），不是大数字。

简历中的技能点必须能回到简历证据片段。证据级分提及、使用、结果:只在技能栏或自我评价出现算提及；经历或项目写明任务中的使用算使用；写明本人责任以及数字、交付物或可核对结果算结果。最高只有提及时记简历证据不足。证据级不替代熟练级,不进入匹配分；方向结论可分别比较两个岗位的使用与结果证据数量,每条模型评价都能展开原文。

学习路径按换档条件排序，不是按缺口出现顺序取前 5。每步四样：技能点、职责段摘录、一条能打开的链接、为何先补它。不自建课程库。赛题那一对可预置几门课的 URL，不进谱。路径覆盖抽检换档条件上的技能点，不定准确率。

同一简历只在可诊断岗位中逐层比较匹配档位、必备技能覆盖、有简历证据的岗位专属技能数和可迁移工程能力数,最后以数据新鲜度与证据充分度破同序,得到三个岗位推荐；用户看到每岗前两条理由并可改选两个。方向结论由模型解释必备技能覆盖、简历证据级、可迁移工程能力、岗位专属经历和经验学历风险,不生成新的综合分；默认故事是大模型应用工程师 ↔ Agent 工程师。换岗停在 done,不重传简历。

### 审核与直通

待审是幻觉防控的最后一闸。新岗位首次发布和既有岗能力更新共用。直通默认关。关着时中高也进待审；开了只跳过中高的人批，演化事件记自动通过。低层证据底线不跳过。

## 信息架构

主导航四项 + 顶栏右「管理」。

| 路由 | 页面 | 谁用 | 职责 |
|---|---|---|---|
| `/` | 总览 | 求职者 | 四领域岗位图；萌芽 / 谱内；新岗位发现与既有岗更新各一条故事，各带打开工作台、对照这份岗。管线折进「本周期怎么算出来的」 |
| `/graph` | 图谱 | 求职者 | 领域 / 技能类目 / 级别筛选；左岗位列表；中当前岗切片（含切片差分）；右定义、独立源、技能点表、证据 |
| `/diagnose` | 诊断 | 求职者 | 上传简历、校对解析结果、从三个推荐岗位中选两个、等待四拍、查看方向结论与对照报告。支持对照链接 |
| `/discover` | 发现 | 求职者 | 候选 / 萌芽 / 成型看板与卷宗。成型列切片。候选只开卷宗。管线、热度、流水的主场 |
| `/admin` | 管理 | 管理员 | 口令门。待审默认页；直通开关；确认 / 驳回 / 证据。低置信可批，不记自动通过 |

诊断 done 报告四组，避免一长串同款列表：

1. **判断**：方向结论、两个岗位的分维度比较、档位与换档条件；缺口集只写「简历未找到证据」,不推断真实能力
2. **定位**：对照小图谱、类目覆盖（类目只导航、不对账）、邻近岗并排（当前档位 + 同领域另一岗；默认赛题那一对；换岗仍停在 done）
3. **行动**：学习路径（按换档条件排序，每步技能点 / 职责段 / 一条链接 / 为何先补）、对账表（技能点 / 对照 / 简历 / 岗位 / 边 / 证据）
4. **解释**：逐项岗位要求、简历命中依据、熟练级差异、简历证据不足、最小岗位证据摘要和计分公式；另列对齐痕迹、观测中（对外写「市场开始提，还没进要求，不算缺口」）、简历多出来的技能点、已覆盖。半档 0.5、加分 0.3 只写在这里

空态与失败：解析失败写原因 + 可重传，不道歉。换简历或离开诊断页则中止本次分析。邻近岗换岗不停分析。

岗位名录不进主导航。从总览图或工作台进某一岗即可。

## 非目标与后续

本期不做：账户体系、历史诊断存档、订阅推送、自建学习内容库、评委 PPT / 演示视频、Timebar、`Resource` 节点。对照链接本期做，不上登录。

Roadmap 后移：登录后保存对照（有人带对照链接回来再做）；追踪萌芽岗做成书签加切片差分，不做推送；课表只挂赛题那一对的 URL，不进谱。

## 给实现的约束

- 求职者第一。管理口令入口可以看见，不做成第二套产品。
- 画面跟原型走。新视觉决策先改原型再改本文。
- 求职者文案用人话；对账表、证据抽屉、术语表用 `CONTEXT.md` 的词。技能类目不对账。观测中不是缺口。
- 17 个规范岗位名是对齐靶子。技能点、要求边、岗位状态从 `data/` 本地 JD 管线长出，不要手录进 `bootstrap.py`。
- 赛题那一对由管线从 JD 快照产出，不要手写状态或演化事件。
- 学习路径按换档条件排序。
- 三项准确率按 `CONTEXT.md`：技能点 set-based F1 ≥0.90。匹配评测喂金标缺口集，不喂解析输出。
